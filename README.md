# Codex 实时用量 · Codex Token Inline

[English](README.en.md) · [实现原理](docs/architecture.md) · [兼容性](docs/compatibility.md) · [致谢与许可](THIRD_PARTY_NOTICES.md)

为 **Codex 工作模式**的回复和进度消息添加一行简洁的 token 用量。默认只显示数字，悬停时查看输入、输出、缓存命中。

> **仅支持 Codex 模式，也就是工作模式。不支持 GPT 普通聊天模式，目前也不计划开发普通聊天模式的 token 显示。** 应用图标或窗口在部分版本中可能叫“ChatGPT”，支持范围取决于使用的模式，而不是图标名称。

**当前版本：0.2.0-alpha.6。** 非 OpenAI 官方插件。原版窗口显示已由本机用户确认，安装和卸载已在同一电脑验证；这仍是早期预览，不代表已经适配所有电脑和客户端版本。

```text
第一段     100 tokens
第二段     50 · 150 tokens
第三段     20 · 170 tokens
```

第一项是本段新增消耗，第二项是同一执行范围内的总消耗。前面的段落冻结，最新段落继续更新；不要把右侧总量再相加。数字并非那段可见文字的字数，还包括本段期间对应模型调用的输入和输出。

- 进行中显示绿色，记录执行结束后变为原生灰色。
- 百万以上保留两位小数，例如 `1.27M tokens`；不足百万使用千分位。
- 悬停依次显示 **输入 → 输出 → 缓存命中**，保留精确数字。
- 总量 = 输入 + 输出。缓存命中属于输入，推理属于输出，都不会再额外相加。
- 根据本地真实用量记录更新，不模拟逐 token 增长，不估算费用或订阅剩余额度。
- 尚未找到唯一对应的本地助手消息记录时，组件保持隐藏；核对成功后才显示，避免串到其他消息。
- 已核对的最新段尚未收到用量记录时显示 `— · 476,637 tokens`：左侧等待数据，右侧保留已记录总量。收到记录后再显示本段数字，避免把暂时未知误写成 0。

## 安装和使用

1. 从 [Releases](https://github.com/xiaoyufengling/codex-token-inline/releases) 下载与你的 Codex 版本兼容的 Windows 安装包，选择 `.exe` 安装器。
2. 双击安装。安装向导显示版本、作者和 GitHub 链接。
3. 正常退出当前 Codex，然后通过桌面或开始菜单中的 **Codex Token Inline** 打开。
4. 进入 **Codex 工作模式**，打开本机任务，查看助手回复下方的用量。

这个入口启动系统已经安装的**原版 Codex**，不复制客户端、不建立第二套客户端配置、不修改原安装包。但之后仍需使用这个增强入口：原来的开始菜单固定图标、原有或自行创建的原版桌面快捷方式，不会自动加载增强。

开始菜单中的 **Manage Codex Token Inline** 可查看版本、作者、参考项目和卸载入口，并切换简体中文 / English；悬停明细随语言设置更新。新版安装包可覆盖更新已识别的本项目安装。卸载前正常退出 Codex并等待约 10 秒，再从 Windows 设置的应用列表或管理页卸载。

启动增强入口时自动检查 GitHub 更新（每天最多自动检查一次，Codex 版本改变时重新检查），只推荐明确支持当前 Codex 的新版本。提供“下载并安装”“稍后”“跳过此版本”，不强制升级、不自动关闭 Codex。下载后核对 SHA-256。管理页可手动检查，或从“所有版本”选择历史发行版。

从 alpha.5 开始，新安装器支持覆盖已有安装并保留语言设置；更新前正常退出运行中的增强。alpha.4 及更早版本没有自动更新检查，需要先手工安装一次当前版本。从 alpha.6 起默认使用结构识别，不按版本号、打包文件名或组件函数名限制接入；结构相同的后续版本可继续使用，关键数据契约变化时才需要修复。

## 支持范围

| 项目 | 当前状态 |
| --- | --- |
| Windows x64 Store Codex 26.901.6511.0，内部版本 26.901.51231 | 本机原版窗口显示已确认 |
| Windows x64 Store Codex 26.903.8094.0，内部版本 26.903.61454 | 结构识别已在原版窗口实际运行并收到经核对的用量 |
| Codex 工作模式中的本地任务 | 支持，受本地记录完整性限制 |
| GPT 普通聊天模式 | 不支持，目前不计划开发 |
| 其他 Codex 版本、macOS、Linux | 未验证，不承诺支持 |
| 原始开始菜单图标、用户自行创建的原版快捷方式 | 不会自动加载增强 |
| 纯思考阶段、尚无回复或进度消息时的占位显示 | 当前 DOM 适配器尚未实现 |

启动时检查消息结构，显示前用本地助手消息记录核对标识与时间。没有证据或存在冲突时暂不显示，避免错配。默认以一次持续执行为统计范围；执行中补充说明仍属同一范围，完成后新发起的问题另算。显式目标可连接多个执行，但目前不会根据自然语言自动判断跨轮长期目标，也不会自动合并不同任务中的子代理用量。

## 我们如何实现

1. **启动原版**：安装器放置轻量启动器、Node 运行环境和本项目代码。启动器通过 Windows 应用激活接口启动原来的 Store 包，并传入本机调试参数。
2. **连接本机接口**：辅助程序使用 Chrome DevTools Protocol（CDP），只连接 `127.0.0.1`，并检查监听端口属于刚启动的原版进程。
3. **等待正常加载**：原版页面完成加载后才添加增强。当前版本不拦截资源、不强制刷新页面，不替换原版文件。
4. **对应消息位置**：不依赖组件名称，从符合结构的原生消息组件读取任务、执行、消息标识和时间，将自己的数字节点放到可见操作栏或消息下方。原有按钮由 Codex 继续管理。
5. **读取本地用量**：增量读取本机 Codex 工作任务记录，对模型响应去重，计算本段和执行范围总量，再通过仅提供数字快照的桥接返回界面。

界面使用约 500ms 的检查节拍，历史冻结数据约 10 秒复核，隐藏页面至少间隔 2 秒；请求耗时和记录落盘节奏会影响实际更新速度。这不是服务端逐 token 实时流。

完整数据流、模块职责、统计边界和限制见 **[实现原理](docs/architecture.md)**。

## 开发、隐私与许可

开发需要 Node.js 22 或更新版本。安装包自带运行环境，普通用户无需手工安装 Node。

```sh
npm ci
npm test
npm run check
```

构建见 [安装器说明](installer/README.md)，参与维护见 [贡献指南](CONTRIBUTING.md)。请先阅读兼容性说明再添加适配。

统计读取本地 CODEX_HOME 或默认 .codex 中的工作任务记录，不读取 auth.json，不上传会话日志。CDP 本身具有较大的页面调试权限，因此不能将端口开放到外网。不要在 issue 中粘贴真实会话、账号资料或私有诊断。

代码采用 MIT 许可。本项目独立维护，不隶属于 OpenAI，也不代表参考项目作者为本项目背书。项目不分发 Codex 客户端文件。参见 [安全说明](SECURITY.md)。
