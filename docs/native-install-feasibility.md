# 原版接入与原始入口的区别

当前 alpha.4 启动系统已安装的原版 Codex，通过本机 CDP 添加自己的 DOM 用量组件，不复制客户端、不修改原安装包。实现细节见 [架构](architecture.md)，来源见 [GitHub 接入调研](github-integration-research.md)。

## 已验证的接入路径

Windows Store 包通过 IApplicationActivationManager 激活，使用仅绑定 127.0.0.1 的调试端口。启动器检查端口属于原版进程，辅助程序检查客户端源码指纹，再等页面正常加载完成后挂载组件。普通启动中不拦截资源、不强制刷新。

## 尚未实现的原始入口支持

必须使用 Codex Token Inline 增强入口。原来的开始菜单固定图标和自行创建的原版快捷方式不会自动传入调试参数，因此不会自动加载用量显示。

开发前端地址和开发构建的 Chromium 配置开关不构成已验证的生产接入方案。项目不通过修改 WindowsApps 权限、原包、签名或完整性校验来解决原始入口问题。

## 历史路线

独立客户端副本、离线 ASAR 补丁以及 alpha.1 的资源响应替换是旧实验，均不是当前默认安装方案。源码保留相关测试基线，不能据此宣称这些路线满足当前产品要求。

当前只验证过指定 Windows 构建；跨版本、跨设备及原始入口集成仍需要独立验证。参见 [兼容性](compatibility.md)。
